## 1 实验概述

本实验实现单用户、本地运行的学习任务管理 Web 应用 StudyTask：后端 Python + Flask + SQLite，前端为服务端渲染的 HTML 页面，无前端框架、无 JavaScript 依赖。应用支持任务的新建、查看、编辑、删除、状态调整、按课程/状态/优先级组合筛选、逾期与即将到期标记，以及首页统计；数据保存在本地 SQLite 文件，重启不丢失。

## 2 需求与实现范围

实现 SRS A.3 的全部功能需求：

- FR-01～FR-04：新建（校验名称、课程、截止日期）、列表与详情、编辑、删除（二次确认）；
- FR-05～FR-06：状态三态调整；按课程、状态、优先级筛选且可组合；
- FR-07：逾期与即将到期标记（已完成任务不显示）；
- FR-08～FR-10：首页统计、数据持久化、中文界面与错误提示。

未实现（SRS A.5 明确的范围外内容）：注册与多用户权限、任务共享、邮件短信提醒、第三方日历、移动端应用。云部署不在需求范围内，本次额外用免费 PaaS 部署作演示，不改变系统单用户本地的定位。

## 3 系统设计

- 分层：`app.py` 负责路由与页面渲染；`tasks.py` 为纯函数层（表单校验、日期判定、统计）；`db.py` + `schema.sql` 负责数据访问。
- 数据表 `tasks`：id、name、course、description、due_date、priority、status、created_at、updated_at；priority 与 status 用 CHECK 约束限定取值，course、status、priority 建索引。
- 关键口径：逾期 = 未完成且截止日期早于今天；即将到期 = 未完成且今天 ≤ 截止日期 ≤ 今天 + 3 天；已完成任务不做任何标记。完成率 = 已完成 / 总数 × 100 取整四舍五入，总数为 0 时为 0%。
- 健壮性：参数化 SQL 防注入；Jinja2 自动转义；非法输入回填表单并显示字段级错误；不存在的任务返回 404 页面。

## 6 问题与修复

**问题一：数据库位置依赖启动目录。** 从工作区根目录启动 `app.py` 时，数据库被创建到“启动目录/instance”，与项目数据分离。定位：`app.instance_path` 会随启动方式变化。修复：改为以 `app.py` 所在目录为基准固定 `instance/studytask.db`，并在启动前确保父目录存在。验证：从不同目录启动均写入项目内数据库，重启后数据仍在。

**问题二：开发环境 pip 无法创建临时目录。** 现象：安装依赖时报 `PermissionError`（`tempfile.mkdtemp` 生成的目录不可访问）；同时官方源文件服务器 DNS 解析失败，安装长时间卡死。修复：改用国内镜像源；在项目外放置 `sitecustomize.py` 补丁改写 `mkdtemp` 的目录权限，并用 `ensurepip` 引导虚拟环境。验证：12 个依赖安装成功，测试可正常运行。

**问题三：pytest 缓存目录不可写。** 现象：首次运行报 `PytestCacheWarning`，并在项目根残留不可读目录。修复：`pytest.ini` 增加 `-p no:cacheprovider`。验证：复跑无警告，15 passed。

## 7 部署

部署平台为 PythonAnywhere 免费版：从 GitHub 仓库 clone 代码 → 创建 virtualenv 并 `pip install -r requirements.txt` → Web 标签选择 Manual configuration，WSGI 文件写入 `from app import app as application` → 静态文件映射 `/static/`。线上地址 <https://iouyun07.pythonanywhere.com>，服务器端测试 15 passed；SQLite 数据存于 `~/StudyTask/instance`，服务重启不丢失。

## 8 结论与限制

系统完成 SRS 规定的全部功能，自动化测试与人工验收均通过，并已部署上线。已知限制：单用户使用、无登录与权限控制；SQLite 单文件不适合高并发写入；任务列表不分页（按约 200 条需求规模设计）；日期以服务器/本机当天为准，未做时区转换；未做移动端适配；逾期与即将到期仅页面标记，不发送提醒（提醒属范围外）。
